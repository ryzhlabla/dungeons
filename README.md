# Dungeon — приключение на шестьдесят две сцены

При `/start` бот отправляет новую стартовую карточку в конец чата с кнопкой
«Продолжить» для сохранённой игры. После успешной отправки удаляет прежнюю
карточку и текущее сообщение `/start`. Если Telegram запрещает удаление старой
карточки, бот пробует убрать с неё кнопки. Уже накопленные сообщения команд
автоматически не очищаются. Прогресс и число ходов сохраняются. Если новую
карточку отправить не удалось, прежняя не удаляется; можно повторить `/start`.

Конец дороги → дом → ручей → решётка → вход в пещеру → первый подземный зал → грот обломков → птица → Зал Горного Короля. Можно взять лампу, зажечь, погасить, оставить в любом месте и подобрать снова. Есть осмотр, подсказки, дневник, прогресс и подтверждение новой игры.

## Запуск на Windows

Нужен Python 3.12 или новее. В PowerShell:

~~~powershell
cd "C:\Users\ryzhi\OneDrive\Рабочий стол\Игра подземелья\dungeon"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
~~~

В Telegram откройте официальный @BotFather, отправьте /newbot и следуйте его подсказкам.
В .env замените replace_me на полученный токен:

~~~env
BOT_TOKEN=ваш_токен
LOG_LEVEL=INFO
~~~

Сохраните файл и запустите:

~~~powershell
.\.venv\Scripts\python.exe -m app.bot
~~~

Откройте личный чат со своим ботом и отправьте /start.
Остановка — Ctrl+C в терминале. Пока программа выключена, бот не отвечает.
При следующем запуске повторять установку и копирование .env не нужно.
Активация окружения и изменение ExecutionPolicy не требуются.

Если .venv уже подготовлено, начните с Copy-Item и настройки .env.
Не копируйте .env.example поверх своего уже заполненного .env.

## Где картинки и как их менять

Все картинки — обычные локальные файлы. Полный список с вариантами — в КАРТА_ШАГОВ.md:

| Файл | Где показывается |
| --- | --- |
| media/scenes/001_Конец_дороги.jpg | Конец дороги и стартовый экран |
| media/scenes/002_Внутри_дома.jpg | Дом |
| media/scenes/003_У_ручья.jpg | Ручей |
| media/scenes/004_Решётка_у_скал.jpg | Решётка |
| media/scenes/005_Вход_в_пещеру.jpg | Вход в пещеру |
| media/scenes/006_Первый_подземный_зал.jpg | Первый подземный зал |
| media/scenes/007_Грот_обломков.jpg | Грот обломков |
| media/scenes/008_Грот_птицы.jpg | Грот птицы |
| media/scenes/009_Зал_Горного_Короля.jpg | Зал Горного Короля |

1. Откройте папку media/scenes в Проводнике.
2. Сохраните свою картинку как JPG с тем же именем вместо соответствующего файла.
3. В боте выйдите из сцены и вернитесь в неё. Новая картинка загрузится автоматически.

Перезапуск не нужен. Бот проверяет содержимое файла перед показом; сохранённая в Telegram старая копия не мешает замене.
Не переименовывайте PNG в JPG: экспортируйте его в JPEG через графический редактор.
Рекомендуется горизонтальная картинка 1280×720, до 5 МБ. Текст на картинке не нужен: описание и кнопки добавляет бот.
Для PNG сохраните основу имени и замените расширение в media файла game.json. При переименовании основы одинаково переименуйте текст и картинку, сохраните номер и обновите ссылки media и text_file.
Изображения на экранах рюкзака и меню соответствуют текущему месту.
Иллюстрации статические: после подбора лампы изображение дома не меняется, состояние передаётся текстом и кнопками.

Для размещения на Ubuntu достаточно перенести весь проект вместе с папкой media.
Хостинг картинок, облачное хранилище и отдельные ссылки не нужны.
Исходные промпты иллюстраций: media/PROMPTS.md.

## Сохранения

### Откат для проверки игры

Остановите бота через Ctrl+C. В PowerShell из папки `dungeon`:

```powershell
# Предварительный просмотр, без изменения сохранения
.\.venv\Scripts\python.exe -m app.save_tools rewind-star
# Вернуться в Звёздный свод ДО изучения карты
.\.venv\Scripts\python.exe -m app.save_tools rewind-star --apply
# Или сразу ПОСЛЕ изучения карты
.\.venv\Scripts\python.exe -m app.save_tools rewind-star --map-studied --apply
```

Команда убирает открытия всех сцен после 020 и их события. Сохраняет прежние предметы,
а оставленные в поздних сценах возвращает в рюкзак. По записи о первом посещении
Звёздного свода обрезает последующий дневник и отменяет изученный позднее короткий
спуск с балкона. Если запись уже выпала из дневника, оставляет одну запись о своде
и сбрасывает короткий спуск. **Это восстановление этапа, а не точный исторический
снимок: счётчик ходов и прочие прежние предметы остаются текущими.**

Перед каждой записью создаётся JSON-копия сохранения игрока в `data/backups/`.
Для отмены отката используйте путь к копии, напечатанный командой:

```powershell
.\.venv\Scripts\python.exe -m app.save_tools restore --file "data/backups/ИМЯ_КОПИИ.json" --apply
```

При нескольких игроках для отката укажите `--user-id ЧИСЛО`.
После изменений запустите бота и выберите `/start` → «Продолжить».
Во время отката и восстановления бот должен быть остановлен.

Прогресс каждого игрока хранится отдельно в data/prototype.sqlite3. Файл создаётся автоматически.
Он переживает перезапуск. Для резервной копии остановите бота и скопируйте папку data.
Не удаляйте её при замене картинок. Токен и сохранения исключены из Git.

Это локальный прототип с SQLite и одним процессом бота. Не запускайте два экземпляра с одним токеном.
Для production позже предусмотрен переход на PostgreSQL.

## Что проверить в Telegram

- /start → начать → войти в дом → взять лампу.
- Открыть рюкзак, зажечь и погасить лампу.
- Оставить лампу у ручья, уйти, вернуться и подобрать снова.
- Осмотреть все шестьдесят два места, открыть подсказку, дневник и прогресс.
- Обычная навигация обновляет одну карточку и не засоряет чат.
- Начать новую игру: сначала появляется подтверждение.
- Перезапустить программу: кнопка «Продолжить» возвращает сохранённый прогресс.
- Заменить JPG и повторно открыть сцену.
- Если карточка удалена или обновление не прошло, отправить /start.

Осмотр и меню не тратят ходы. Топливо пока не расходуется. Без света герой отказывается идти глубже; вернуться из зала можно всегда. Смертей и полной пещеры пока нет.
Это самостоятельная небольшая адаптация начала приключения, а не импорт оригинального C-движка.
Сюжетные переходы находятся в games/colossal_cave/game.json, а тексты — в папке texts; правила предметов пока реализованы в небольшом Python-движке.

## Номера шагов, тексты и карта

Начните с [КАРТА_ШАГОВ.md](КАРТА_ШАГОВ.md): там указаны действия и ссылки на тексты и картинки.
Номер — постоянный номер сцены в каталоге, а не счётчик ходов и не обязательный порядок прохождения.
001 — конец дороги, 002 — дом, 003 — ручей. Новым сценам даём новые номера; старые не меняем.

Тексты сцен:
- texts/scenes/001_Конец_дороги.json
- texts/scenes/002_Внутри_дома.json
- texts/scenes/003_У_ручья.json

В каждом файле title — заголовок, text — основное описание, inspect — осмотр,
buttons — подписи переходов. Правьте значения справа от двоеточия, сохраняя кавычки и запятые.
Встроенные кавычки удобнее писать как «ёлочки». Перенос строки внутри текста задаётся через \n.
Не меняйте ключи слева: это ссылки для программы.

Общие тексты:
- texts/interface/000_Экраны_и_кнопки.json — старт, меню, рюкзак, описание лампы, подсказки, кнопки;
- texts/events/002_Лампа_и_дневник.json — сообщения о действиях и записи дневника.

000 означает общий интерфейс, 002 у событий — связь с лампой, впервые найденной в доме.
Общие строки используются сразу в нескольких сценах.
Фрагменты {value_0}, {value_1} в тексте — места для автоматически подставляемых значений.
Сохраняйте их без изменений; окружающий текст можно менять.
При DEV_TEXT_RELOAD=true сохраните JSON и отправьте /refresh или нажмите кнопку. При false нужен перезапуск.
Старые записи дневника уже сохранены и не переписываются; новые используют изменённые тексты.

Для проверки файлов: .\.venv\Scripts\python.exe -m app.validate
После изменения названий и переходов обновите карту: .\.venv\Scripts\python.exe -m app.catalog
Визуальные ориентиры будущих иллюстраций описаны в media/СТИЛЬ.md.

## Сцены и сценарные состояния

Номер места остаётся постоянным. Сценарий — вариант того же места, выбранный по текущему состоянию мира.
Для грота обломков:
- 007.01 — базовое описание: птица ещё в своём гроте.
- 007.02 — клетку забрали: меняются картинка и описание плиты.
- 007.03 — птица в клетке: соседний грот больше не поёт.
- 007.04 — птица улетела: тихий грот и нейтральная кнопка перехода.
- 007.05 — темнота: скрывает зрительные детали.

В тексте 007_Грот_обломков.json редактируются text_captured, inspect_captured, text_released, inspect_released и buttons_quiet.
Условия находятся в variants соответствующей сцены в game.json. Применение идёт сверху вниз: вариант меняет только перечисленные поля.
Поэтому изменение текста о птице не отменяет состояние картинки с клеткой или без неё. Темнота применяется последней.
Местонахождение птицы берётся из сохранения; отдельный счётчик этапов не нужен. Старые сохранения совместимы.
При DEV_TEXT_RELOAD=true карта обновляется вместе с текстом; иначе запустите python -m app.catalog и перезапустите бота.


## Правки текста без перезапуска (разработка)

В локальном .env включён DEV_TEXT_RELOAD=true. После установки этой версии бота один раз перезапустите процесс.
Затем сохраните правку JSON в texts/ и нажмите кнопку в боте либо отправьте /refresh.
/refresh обновляет текущий экран без хода и смены места. Уже отправленная карточка сама по таймеру не обновляется.
Карта шагов автоматически обновится из той же успешно проверенной версии текстов.

Для production установите DEV_TEXT_RELOAD=false и перезапустите процесс. Это также значение по умолчанию и в .env.example.
При false файлы текстов не проверяются при нажатиях: бот использует версию, загруженную при запуске.
Изменение самого флага требует перезапуска.

При ошибке JSON, удалённом файле, изменении ключей или переменных шаблона продолжает работать последняя корректная версия.
Причина записывается в терминал. Исправьте файл и снова отправьте /refresh.
Режим обновляет значения в существующих текстовых файлах (включая подписи кнопок, описания вариантов, события и подсказки).
Изменение game.json, переходов, условий, списка файлов или структуры JSON требует перезапуска.
Исторические записи дневника сохраняют текст, действовавший в момент события; новое событие получит новый текст.
/refresh очищает временное уведомление о предыдущем действии и показывает актуальный экран.

Полная карта включает каждое текстовое поле сцены, все условия вариантов, описания при возвращении,
подсказки, сообщения об успехе и отказе, кнопки и общие тексты предметов и интерфейса.
Она генерируется из JSON: редактируйте исходный текст, а не карту.


## Отдельные картинки состояний и возвращений

В `games/colossal_cave/game.json` у каждой сцены и каждого элемента `variants`
есть `media` (обычная картинка) и `return_media` (картинка повторного входа).
Карта шагов перечисляет все эти настройки и условия выбора.

Чтобы добавить картинку, например для возвращения после отлёта птицы:

1. Положите файл `007.04_Возвращение_после_отлёта_птицы.jpg` в `media/scenes/`.
2. В верхнем разделе `media` добавьте запись
   `"scene.debris_grotto.released.return": "media/scenes/007.04_Возвращение_после_отлёта_птицы.jpg"`.
3. В сцене `debris_grotto`, варианте с `id: "007.04"`, замените
   `"return_media": null` на `"return_media": "scene.debris_grotto.released.return"`.
4. Выполните `python -m app.catalog` и перезапустите бот.

`null` не требует отдельного файла. Пустое `return_media` сохраняет обычную
картинку; пустое `media` варианта сохраняет предыдущее подходящее изображение,
а если его нет — базовое. Готовые иллюстрации состояний сохранены.
Варианты применяются сверху вниз: каждый может задать обычную картинку и
затем картинку возвращения. Темнота имеет последний приоритет.

Признак возвращения сохраняется при осмотре, открытии меню, `/refresh` и
перезапуске. В старом сохранении он определяется при следующем переходе.
Флаг `DEV_TEXT_RELOAD` обновляет тексты; новые пути картинок требуют перезапуска.
Заменить содержимое уже назначенного JPG можно без перезапуска:
новая версия загрузится при следующем обновлении карточки.
